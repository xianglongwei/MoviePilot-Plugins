# PigGo 儿童动画本地元数据插件方案

更新日期：2026-08-30

> 本文保留方案推导和技术研究过程。统一的产品需求与验收基线见 `docs/PigGoKidsMetadata_Product_Requirements.md`；两者冲突时以产品需求文档为准。

## 需求判断

用户在 PigGo 儿童区下载儿童动画，很多内容在 TMDb 没有条目或信息不完整，导致 MoviePilot 无法识别、整理和入库。用户明确不希望依赖人工校正，而是希望插件尽量自动从下载结果本身恢复正确片名、季集和元数据，再让 MP 能继续整理。

更新后的核心判断：不要把“写回 TMDb”作为自动闭环的必要条件。TMDb 官方 API 当前没有创建/编辑电影、剧集、季、集基础资料的公开写入接口；可写接口主要是账号收藏、观看清单、列表、评分和认证会话。TMDb 贡献更适合作为“生成草稿，由人提交或复核”的旁路，而不是让插件自动提交后等待 TMDb 变成 MP 可识别来源。

更稳的自动闭环是：插件注册一个 MoviePilot 插件媒体来源，例如 `piggokids`。当 TMDb/Douban/Bangumi 等原生来源识别失败时，插件通过 MoviePilot 的 `MediaRecognize` 补充识别链返回带有 `media_source=piggokids` 和稳定 `media_id` 的 `MediaInfo`，让后续下载、整理、刮削和媒体库刷新继续运行。

本次进一步修正：不要把“读取种子文件”理解为能直接读取 NFO 和海报内容。`.torrent` 是 BitTorrent metainfo，主要包含任务名、文件路径列表、文件大小、分片哈希、tracker 等信息。它可以告诉插件下载内容包里是否有 `*.nfo`、`poster.jpg`、`fanart.jpg` 之类文件，但这些文件的实际内容要在下载完成后的真实目录中读取。因此第一版应把“下载后扫描实际文件夹”作为主链路，把种子元信息作为文件列表与任务映射辅助。

已观察到 PigGo 页面是 NexusPHP 风格。儿童区列表页提供资源标题、分类、大小、做种/下载/完成等列表字段；详情页还提供副标题、标签、类型、来源、媒介、编码、音频编码、分辨率、制作组、画质、文件数、封面图、简介、年份、产地、类别、导演等字段。页面也包含账号状态、下载链接和令牌，这些信息不能写入文档或插件日志。

## 推荐方案

做一个新插件：`PigGoKidsMetadata`。

插件职责：

- 注册 MoviePilot 插件媒体来源：`piggokids`。
- 从 RSS、用户粘贴的种子/磁力/下载链接、MoviePilot 搜索结果或 PigGo 详情页建立候选任务；第一版优先 RSS 和用户提供链接，减少直接抓登录页面。
- 监听下载加入、下载完成和整理失败事件，保存下载 hash、站点条目、下载目录与种子元信息之间的映射。
- 下载完成后扫描真实下载内容包，优先解析随包 NFO、海报、背景图、字幕和媒体文件名，生成本地媒体条目。
- 解析站点标题、副标题、简介、文件列表和种子元信息，作为随包元数据不足时的辅助。
- 在 TMDb/Douban/Bangumi 等来源无结果或低置信度时，自动返回 `piggokids:<id>` 媒体身份作为识别兜底。
- 对 TMDb 已存在但信息不完整的内容，优先让 MP 使用 TMDb 身份整理，同时本地生成更完整的 NFO/图片；另生成 TMDb 贡献草稿。
- 对 TMDb 不存在的内容，使用 `piggokids` 身份整理，并生成 Emby/Jellyfin 可读取的目录、文件名、`.nfo` 和图片。
- 整理完成后触发媒体服务器刷新。

不建议第一版直接改 MoviePilot 核心识别链，也不建议伪造 TMDb ID。V3 已有插件补充识别链和插件扩展媒体来源，应该使用这条正规扩展路径。

## 用户提出的 RSS 下载闭环

用户提出的新流程可以做，但需要调整 TMDb 这一环：

```text
RSS / 搜索 / 用户粘贴下载链接
-> 插件候选列表
-> 用户选择下载
-> 调 MoviePilot 下载器加入任务
-> 下载完成后扫描实际文件
-> 原生识别成功则使用原生身份
-> 原生识别失败则使用 piggokids 插件媒体身份
-> MP 整理入库、生成或保留 NFO/图片、刷新媒体库
-> 可选生成 TMDb 贡献草稿
```

其中“编辑到 TMDb，然后再次触发 MP 识别”不适合作为自动主链路。TMDb 官方 OpenAPI 可以搜索电影/剧集，也支持账号认证；可写能力主要是收藏、观看列表、列表、评分等用户行为。`/3/list/{list_id}/add_item` 的 “Add Movie” 只是把已有 `media_id` 加入用户自定义列表，不是创建电影条目。当前没有公开的创建或编辑电影、剧集、季、集基础资料接口。因此即使用户提供 TMDb API Key 或账号，也不能通过正规 API 自动新增/修改影片资料。

实际应拆成两条链：

- 主链：插件本地识别和 `piggokids` 媒体来源，保证下载完成后能自动整理入库。
- 旁路：TMDb 查询和贡献草稿。如果 TMDb 已有条目但信息不完整，插件生成待补充字段、图片和来源证据，由用户手动提交或复核。

## 第一版功能范围

第一版建议做成可落地的闭环，不碰高风险网页自动投稿：

1. RSS 管理

   - 支持配置 PigGo 儿童动画 RSS URL。
   - RSS URL 可能含 passkey，只保存在插件配置或 MoviePilot 配置中，不写日志、不展示完整 URL。
   - 定时拉取 RSS，解析标题、发布时间、详情页链接、下载链接、分类、大小、简介字段。
   - 对同一 RSS item 做去重，避免重复加入下载器。

2. 候选选择与搜索

   - 插件页面显示 RSS 候选列表，支持关键词搜索、类型过滤、已下载/未下载过滤。
   - 支持用户粘贴种子 URL、磁力链接或下载链接。
   - 对候选先做轻量解析，展示推测片名、季号、集数、分辨率、文件数和风险提示。

3. 加入下载器

   - 优先调用 MoviePilot 的下载接口，把资源交给 MP 已配置的下载器，不在插件里单独保存下载器账号。
   - 如果 MP 要求识别后才能下载，插件先尝试原生识别；失败时可用 `allow_unrecognized` 或 `piggokids` 身份加入，具体取决于用户 MP 版本接口能力。
   - 下载任务尽量使用独立保存目录或下载器分类/tag，例如 `piggokids`，避免所有资源混在同一个目录后无法分组。

4. 下载后增强识别

   - 监听下载加入、下载完成、整理失败。
   - 根据 hash、下载器、保存目录和种子文件列表定位真实下载内容包。
   - 优先读取随包 NFO、海报、fanart、字幕和媒体文件名。
   - 对原生识别失败的内容返回 `media_source=piggokids`、`media_id=<stable id>` 的 `MediaInfo`。

5. 整理与刮削

   - 先走整理预览，确认目标目录和文件名不会覆盖已有库。
   - 高置信度自动调用 MP 整理；低置信度进入冲突队列。
   - 对 TMDb 不存在内容，生成 Emby/Jellyfin 可读的本地 NFO 和图片。

6. TMDb 辅助

   - 用 TMDb API 搜索是否已有条目。
   - 有准确条目时优先保留 TMDb 身份。
   - 信息不完整时生成贡献草稿，不自动提交。
   - 无条目时记录“TMDb 缺失”，不阻塞 `piggokids` 本地入库。
   - 对已经绑定 TMDb ID 的条目，可以使用 TMDb changes 接口定期检查资料是否被别人更新，再触发 MP 重新刮削或刷新本地缓存。

## 关键问题

- RSS 下载链接里可能带站点私密 passkey，插件日志和页面展示必须脱敏。
- 如果所有下载都落在同一个目录且不保留种子根目录，下载后分组会变难；应尽量用专用目录、分类或 tag。
- 用户粘贴下载链接时，插件不一定能从链接本身得到站点详情页，需要靠种子文件列表和下载后扫描补足。
- MoviePilot 原生下载流程可能在识别失败时返回 `requires_confirmation`。不同 MP 版本对未识别下载和插件来源下载的支持要实测。
- 儿童动画常见“合集、多季混包、特别篇、剧场版混在一起”，不能只按文件数量粗暴生成一季。
- TMDb API Key 不能解决自动新增/编辑 TMDb 条目的问题，只能用于查询和账号级用户行为。
- TMDb `list-add-movie` 只能把已经存在的 movie ID 加入列表，不能提交新电影资料。
- TMDb changes 接口只能读取最近变更的 ID 和字段历史，适合监控已有条目更新，不适合新增或编辑条目。
- `themoviedb`、`douban`、`bangumi` 都不适合作为“公开 API 自动新增/编辑公共影视条目”的主链路。TMDb 公开写接口偏账号行为；Bangumi v0 公开写接口偏用户收藏、角色/人物收藏和目录；豆瓣没有可依赖的官方公开影视条目写入 API。
- 低置信度不应无人值守入库，尤其是同名节目、年份缺失、季号不明或 NFO 与文件名冲突时。

## 自动化分层

优先级从高到低：

1. 下载内容包里的随包元数据

   下载完成后优先扫描真实目录树。若存在 `tvshow.nfo`、`movie.nfo`、同名 `*.nfo`、`poster.*`、`fanart.*`、`season*.jpg`、字幕文件或发行说明，插件先从这些文件抽取片名、原名、年份、季号、集数、简介、图片和语言信息。随包 NFO/图片比站点标题和全网搜索更接近发布者本意，也最适合儿童动画这种外部数据库缺失的资源。

2. 已有 TMDb 精确命中

   如果 TMDb 有正确条目，插件不替换 MP 的主身份。只在本地 NFO、封面或媒体服务器层补充缺失字段，并生成 TMDb 贡献草稿。

3. 其它公开元数据源命中

   依次尝试 Douban、Bangumi、IMDb、TVDB、AniList、官方发行平台、出品方页面、维基类公开资料等。不同来源返回同名但年份/季号/集数冲突时，不自动整理到正式媒体库。

4. PigGo 详情页命中

   PigGo 详情页通常能提供最贴近当前资源的标题、集数、年份、简介、封面、文件数、画质和制作组。它是儿童动画资源的高价值事实源，但仍要过滤站点声明、下载令牌、账号状态和站内敏感信息。

5. 种子元信息和下载器文件列表命中

   种子元信息和下载器文件列表对季集识别非常重要，尤其适合确认目录名、媒体文件数量、`S01E01`、总集数、合集拆分和单集文件顺序。但它们通常不能提供可靠简介、导演、产地或封面，也不能替代下载目录里的 NFO/图片内容。

6. 全网搜索生成候选

   全网搜索只作为候选收集，不直接作为最终事实。插件必须记录来源 URL、字段来源和置信度，不能把无法溯源的 LLM 生成内容写入元数据。

## 关键工作流

1. 采集站点条目

   插件配置 PigGo 站点名称或基础地址，优先复用 MoviePilot 已配置站点的 Cookie/请求能力，不重复保存账号 Cookie。插件只读取列表和详情页，不自动点击下载链接。

2. 生成解析结果

   从标题和详情中提取：

   - 中文片名、英文名、别名
   - 年份
   - 类型：电影、剧集、合集
   - 季号：`S01`、`第 1 季`
   - 集数：`全 104 集`、文件列表数量、单集编号
   - 分辨率、来源、编码、音轨、制作组
   - 产地、类别、导演、演员、简介
   - 封面图 URL

3. 建立插件媒体来源条目

   插件来源标识建议：

   ```text
   media_source = piggokids
   ```

   来源内 ID 建议使用稳定形式：

   ```text
   media_id = piggo:item:<site_item_id>
   media_id = piggo:series:<normalized_title>:<year>
   ```

   同一个节目多季时，节目级条目和季级条目要分开，不要把不同季、剧场版、合集和重制版混成同一个身份。

4. 自动识别补充

   插件监听或实现 MoviePilot V3 的媒体补充识别能力。原生识别失败、没有远端身份或请求级指定 `source=piggokids` 时，插件返回标准 `MediaInfo`：

   ```json
   {
     "media_source": "piggokids",
     "media_id": "piggo:item:30876",
     "type": "电视剧",
     "title": "帮帮龙出动",
     "original_title": "帮帮龙出动",
     "year": "2015",
     "season": 1,
     "number_of_episodes": 104,
     "overview": "...",
     "poster_path": "...",
     "genres": [{"name": "动画"}, {"name": "儿童"}],
     "detail_link": "https://piggo.me/details.php?id=30876"
   }
   ```

5. 下载与完成监听

   第一版保守做法：

   - 用户仍然通过 MoviePilot 的站点搜索、订阅或 RSS 流程下载。
   - 插件通过 MP 的识别补充链让未命中 TMDb 的资源获得 `piggokids` 身份。
   - 插件监听下载添加事件，保存下载 Hash、站点条目、种子元信息、下载目录和用户/下载器上下文。
   - 插件监听下载完成或整理失败事件，使用下载 Hash、下载目录、详情页 ID、下载器文件列表和真实文件名找回本地媒体条目。
   - 如果 MP 下载 API 返回需要确认未识别资源，插件可以在后续版本中对高置信度条目自动补齐 `media_source + media_id` 后重试。

   如果 MoviePilot 无法把未识别资源加入下载，则第二步再扩展“从插件页面加入下载器”的能力，但这会涉及下载器 API 和站点规则，不能作为第一刀。

6. 下载后扫描与本地解析

   下载完成后插件扫描真实下载目录：

   - 先找 `*.nfo`，优先解析 XML/Kodi/Emby/Jellyfin 常见字段；编码不确定时只做安全探测，不把乱码写入最终元数据。
   - 再找 `poster.*`、`fanart.*`、`cover.*`、`folder.*`、`season*.jpg/png/webp`，按媒体服务器约定映射到海报、背景图和季图。
   - 再解析媒体文件名和目录名，识别单电影、单季剧集、多季合集、特别篇、剧场版、试看/sample 和非媒体附件。
   - 如果 NFO 与文件名冲突，以可追溯字段来源和置信度裁决；低置信度进入冲突队列，不无人值守整理。

7. 整理入库

   对剧集建议输出：

   ```text
   儿童动画/<剧名> (<年份>)/Season 01/<剧名> - S01E01 - 第01集.ext
   儿童动画/<剧名> (<年份>)/Season 01/<剧名> - S01E02 - 第02集.ext
   儿童动画/<剧名> (<年份>)/tvshow.nfo
   儿童动画/<剧名> (<年份>)/poster.jpg
   儿童动画/<剧名> (<年份>)/fanart.jpg
   ```

   对电影建议输出：

   ```text
   儿童动画电影/<片名> (<年份>)/<片名> (<年份>).ext
   儿童动画电影/<片名> (<年份>)/movie.nfo
   儿童动画电影/<片名> (<年份>)/poster.jpg
   ```

8. 媒体服务器刷新

   整理完成后，通过 MoviePilot 已配置的媒体服务器能力或插件配置中的 Emby/Jellyfin 信息触发媒体库刷新。优先复用宿主配置，不重复保存 Token。

9. TMDb 贡献草稿

   插件可以把自动补全后的信息生成一个“贡献草稿”：

   - TMDb 搜索结果：是否已有条目，候选 ID 是什么。
   - 建议新增或补充的字段：中文名、原名、年份、简介、类型、季集、海报、背景图。
   - 字段来源：PigGo 详情页、种子文件、公开百科、官方页面等。
   - 冲突提醒：年份不一致、集数不一致、片名别名冲突。

   插件不自动提交 TMDb。原因是官方 API 没有基础资料写入端点，而且 TMDb 贡献通常需要用户账号、人工判断、社区规则和可能的审核/缓存时间。自动浏览器提交也不稳，容易违反站点规则或产生错误数据。

   TMDb changes 接口可以作为贡献后的观察工具：如果某个条目已经有 TMDb ID，插件可以查询电影、人物、剧集的 changed IDs，或查询指定电影/剧集 ID 的字段变更历史；发现相关字段更新后，再清理 MP/TMDb 缓存或触发重新刮削。但它不能替代投稿接口，不能创建条目，也不能修改字段。

## V2 / V3 支持策略

- V3 作为主实现，目录放在 `plugins.v3/piggokidsmetadata/`，索引写入 `package.v3.json`。
- V2 兼容实现放在 `plugins.v2/piggokidsmetadata/`，索引写入 `package.v2.json`。
- V3 代码优先使用 `app.sdk` 稳定接口；V2 用旧接口做最小兼容。
- V3 需要实现 `get_media_source()`，返回 `piggokids` 的展示名、规范来源标识和支持的媒体类型。
- V3 需要通过 `get_module()` 暴露 `recognize_media` / `async_recognize_media`，并按需实现 `search_medias`、`obtain_images`、`get_media_auxiliary_info`。
- V3 也可以监听 `ChainEventType.MediaRecognize`，在原生识别未取得远端身份时回写 `mediainfo`。
- V3 下载链相关能力可利用 `download_added(context, torrent_content, download_dir)` 保存种子元信息和下载目录映射，利用 `transfer_completed(hashs, downloader)` 或 `TransferFailed` 事件触发下载后扫描。
- V3 下载器模块合同里有 `torrent_files(tid, downloader)`，可以在无法直接读取下载目录前先拿任务文件列表，但最终 NFO/海报仍以真实文件系统扫描为准。
- V2 支持下载器监控自动整理和目录监控整理，插件兼容版可走事件监听加定时/目录扫描；若 V2 插件 API 暴露能力不足，则第一版仅提供下载后目录扫描和手动重试整理辅助。
- 两个版本共享解析规则时，可以复制一份纯 Python 解析模块，避免跨目录导入造成插件市场安装问题。
- 依赖尽量少。HTML 解析第一版优先用标准库或宿主已有能力；若必须新增依赖，考虑 `beautifulsoup4>=4.12,<5`，不要引入会影响宿主核心依赖的库。

## 种子与下载内容边界

| 来源 | 能提供 | 不能可靠提供 | 插件用途 |
| --- | --- | --- | --- |
| `.torrent` / 种子元信息 | 任务名、文件路径、文件大小、分片哈希、tracker、infohash | NFO 文件正文、海报图片内容、准确简介、导演、产地 | 保存下载任务映射，提前判断是否有 NFO/海报附件，辅助季集识别 |
| 下载器文件列表 | 下载任务内文件路径、大小、优先级、完成状态 | NFO/海报正文，媒体库目标路径 | 下载未完成时做预判，下载完成后定位真实文件 |
| 下载内容包 | 媒体文件、NFO、海报、字幕、说明文件的实际内容 | 站点账号信息、外部权威 ID | 第一事实来源，生成 `piggokids` 条目和本地 NFO/图片 |
| PigGo 详情页 | 标题、副标题、标签、封面、简介、文件数、年份/产地等站点字段 | 外部权威 ID、账号/下载令牌可公开性 | 作为随包元数据不足时的补充和字段来源 |

## 数据模型草案

`SiteItem`：

- `site`: 站点标识，例如 `piggo`
- `site_item_id`: PigGo 详情页 ID
- `detail_url`: 详情页 URL
- `raw_title`: 原始标题
- `subtitle`: 副标题
- `tags`: 标签
- `file_count`: 文件数量
- `hash`: 种子 Hash，如页面可见

`TorrentMetainfo`：

- `download_hash`: 下载器任务 Hash 或 infohash
- `torrent_title`: 种子任务名
- `root_name`: 种子根目录名
- `files`: 种子声明的路径和大小
- `has_nfo`: 文件列表中是否出现 NFO
- `has_artwork`: 文件列表中是否出现 poster/fanart/cover/folder 等图片
- `source`: `torrent_content` / `downloader_files`

`DownloadedPayload`：

- `source_path`: 下载完成目录或文件路径
- `media_files`: 实际媒体文件列表
- `nfo_files`: 实际 NFO 文件列表
- `artwork_files`: 实际海报、背景图和季图列表
- `subtitle_files`: 字幕文件列表
- `ignored_files`: sample、截图、压缩包、说明文件等非主媒体文件
- `scan_time`: 扫描时间

`LocalMediaItem`：

- `media_source`: 固定为 `piggokids`
- `media_id`: 插件来源内稳定 ID
- `media_type`: `movie` / `tv` / `collection`
- `title`: 中文标题
- `original_title`: 原始标题
- `aliases`: 别名
- `year`: 年份
- `season`: 季号
- `episode_count`: 总集数
- `genres`: 类型
- `area`: 产地
- `summary`: 简介
- `poster_url`: 封面 URL
- `poster_file`: 本地海报路径，如来自下载内容包
- `fanart_file`: 本地背景图路径，如来自下载内容包
- `source_fields`: 每个关键字段的来源，例如 `nfo`、`filename`、`piggo_detail`、`tmdb`
- `confidence`: 自动解析置信度
- `completion_status`: `auto` / `needs_review` / `conflict` / `locked`

`ImportTask`：

- `task_id`: 任务 ID
- `site_item_id`: 对应站点条目
- `download_hash`: 下载任务 Hash
- `torrent_metainfo`: 种子元信息快照引用
- `source_path`: 下载完成路径
- `target_path`: 媒体库目标路径
- `transfer_mode`: 硬链接、复制或移动
- `status`: 待确认、等待下载、整理中、已入库、失败
- `last_error`: 最近错误

## 插件界面

第一版页面建议：

- `站点扫描`：输入或选择 PigGo 儿童区 URL，扫描列表。
- `下载后扫描`：按下载 hash、下载目录或整理失败历史扫描真实下载内容包。
- `自动补全`：展示 TMDb 缺失、已由 `piggokids` 自动补全的条目。
- `冲突队列`：只展示无法安全自动判断的条目，不作为常规流程。
- `整理预览`：展示将要生成的目录、文件名、NFO 和图片，可全局关闭预览进入无人值守模式。
- `贡献草稿`：展示可复制到 TMDb 的字段和来源证据。
- `任务日志`：展示每条入库任务状态和错误。

## 风险与边界

- 不能把 PigGo 的 Cookie、下载令牌、账号状态、魔力值、分享率等敏感信息写入插件日志或文档。
- 不能高频抓取站点页面；应设置速率限制、缓存和手动触发。
- 不自动点击下载链接作为第一版目标，避免误扣魔力或触发站点规则。
- 不能只凭 `.torrent` 判断已经拿到 NFO/海报内容；必须在下载完成后确认真实文件存在并可读取。
- 不能假设所有儿童区资源都是剧集；页面中也有电影、合集、纪录片/科普内容。
- 同一片名可能有多季、多版本、多分辨率、多音轨，必须区分“媒体条目”和“站点条目”。
- 真实整理前必须做 dry-run，展示目标路径，避免覆盖已有媒体库文件。
- 不能把 LLM 或全网搜索的猜测直接写入最终元数据；必须有可追溯来源。
- 对低置信度条目，无人值守模式下应自动暂停并通知，而不是继续整理到错误目录。
- 不要自动提交 TMDb；只生成贡献草稿或打开页面给用户处理。
