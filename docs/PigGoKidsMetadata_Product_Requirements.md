# PigGoKidsMetadata 产品需求文档

状态：需求基线草案  
更新日期：2026-08-30  
目标版本：MoviePilot V2 / V3

## 1. 背景

用户已经本地部署 MoviePilot，并使用 PigGo PT 站点获取儿童动画、儿童电影和低龄节目。部分内容在 TMDb 中没有条目，或标题、年份、季集、图片等信息不完整，导致 MoviePilot 无法识别，继而无法自动整理、刮削和入库。

用户希望增加一个自维护插件 `PigGoKidsMetadata`，把资源发现、选择下载、下载后增强识别、整理入库和媒体库刷新连成自动闭环。插件必须同时支持 MoviePilot V2 和 V3，并进入用户自己的插件仓库。仓库只保留用户自己维护的插件，不恢复上游无关插件。

## 2. 产品目标

插件应实现以下闭环：

```text
PigGo RSS / 用户粘贴下载链接
-> 建立候选资源
-> 用户选择或按规则自动下载
-> 调用 MoviePilot 已配置的下载器
-> 按下载 hash 跟踪任务
-> 下载完成后扫描真实下载内容包
-> 查询已有公共元数据并完成增强识别
-> 原生来源精确命中时沿用原生身份
-> 原生来源缺失时生成 piggokids 本地媒体身份
-> 调用 MoviePilot 整理、刮削和媒体服务器刷新
-> 记录结果；冲突任务进入待处理队列
```

这里的“全自动”是指高置信度任务从采集到入库无需人工介入。证据互相冲突、类型不明、季集无法确定或目标文件可能覆盖已有媒体时，插件必须暂停该任务并保留完整原因，不能无条件猜测后入库。

## 3. 非目标和边界

- 不修改 MoviePilot 核心源码，使用官方插件、事件、媒体来源、下载和整理扩展能力。
- 不伪造 TMDb、豆瓣或 Bangumi ID。
- 不把自动新增或编辑 TMDb 公共条目作为主流程。TMDb 官方公开 API 没有创建或编辑影视基础资料的端点。
- 不使用 TMDb 的 `list-add-movie` 创建影片；该接口只能把已经存在的电影 ID 加入用户列表。
- 不使用 TMDb changes 接口写资料；它只能读取已有条目的近期变化。
- 第一版不依赖自动操作 PigGo 登录页面。资源入口优先使用用户配置的 RSS 和用户粘贴的链接。
- 第一版不自动模拟浏览器向 TMDb 投稿。可以生成贡献草稿、来源证据和待补字段。
- 不在插件里重复保存 qBittorrent、Transmission 或媒体服务器账号，优先复用 MoviePilot 已配置的服务。

## 4. 核心领域对象

### 4.1 站点条目

来自 PigGo RSS 或详情页的资源记录，至少保存站点内稳定标识、标题、发布时间、详情页引用、下载引用、大小和分类。包含 passkey、Cookie、token 的 URL 只能以受保护形式保存，展示和日志必须脱敏。

### 4.2 下载任务

插件发起或接管的 MoviePilot 下载任务。至少关联插件任务 ID、下载器、下载 hash、下载目录、种子根目录、种子文件列表、当前状态和对应站点条目。

### 4.3 下载内容包

下载完成后的真实目录树，包括视频、字幕、NFO、海报、背景图和说明文件。它是下载后识别的优先事实来源。

### 4.4 本地媒体条目

插件为一部电影、一个剧集、一个季或一个明确合集维护的媒体记录。它必须有稳定的 `media_source=piggokids` 和来源内 `media_id`，并记录每个字段的来源、置信度和冲突状态。

### 4.5 识别决策

一次资源识别的可审计结果，包含候选身份、采用身份、字段证据、置信度、拒绝原因和后续动作。识别失败不能只记录一条模糊错误消息。

## 5. 数据来源优先级

字段可以从多个来源合并，但不得把不可追溯的模型生成文本当成事实。默认优先级如下：

1. 下载内容包中的 NFO、海报、背景图、字幕和目录结构。
2. TMDb、豆瓣、Bangumi 等公共来源的精确现有条目。
3. PigGo 站点条目的标题、副标题、简介、封面、标签和文件列表。
4. `.torrent` 元信息和下载器文件列表。
5. 可追溯的官方发行方、出品方或节目页面。
6. 其它全网搜索结果，仅用于生成候选。

`.torrent` 只包含任务名、路径、大小、分片和 tracker 等种子元信息。它可以证明发布包声明包含某个 NFO 或图片文件，但不能在下载前提供这些文件的正文或图像内容。

## 6. 功能需求

### FR-01 RSS 来源管理

- 用户可以配置一个或多个 PigGo 儿童资源 RSS 地址。
- 插件可以定时拉取、手动刷新、解析和去重 RSS 条目。
- RSS 地址中的 passkey 或身份参数不得出现在日志、通知、错误详情和普通页面文本中。
- 插件记录最近成功时间、HTTP 状态、解析数量和脱敏后的错误原因。

### FR-02 候选资源与搜索

- 插件页面显示未下载、下载中、已完成、失败和已忽略的候选资源。
- 支持按关键词、分类、发布时间、状态和媒体类型筛选。
- 支持用户粘贴磁力链接、种子下载链接或 MoviePilot 可接受的资源链接。
- 对同一 RSS GUID、站点条目 ID、下载 hash 或 torrent infohash 去重。
- 第一版的“搜索”是对已抓取 RSS 候选的本地搜索；直接搜索 PigGo 登录页面属于后续增强能力。

### FR-03 下载发起

- 用户可以从候选条目发起下载，也可以启用明确的自动下载规则。
- 插件调用 MoviePilot 下载链和已配置下载器，不直接管理下载器凭据。
- 识别尚未完成时，插件应使用 MoviePilot 当前版本支持的未识别下载能力，或先建立 `piggokids` 媒体身份再提交。
- 每个任务优先使用专用下载分类、tag 或保存目录 `piggokids`，即使用户的下载根目录是共享的。
- 添加成功后必须持久化下载 hash、下载器、目录、种子文件列表和站点条目映射。

### FR-04 下载状态跟踪

- 插件监听下载加入、下载完成、整理完成和整理失败事件。
- 宿主事件缺失或重启后，插件可以根据持久化任务和下载器状态恢复跟踪。
- 同一事件重复送达时处理必须幂等，不能重复下载、重复整理或重复生成库条目。
- 单文件、带根目录、多季合集和共享下载根目录均不能仅靠目录名关联，必须优先使用 hash 和文件列表。

### FR-05 下载后内容扫描

- 下载完成后扫描该任务实际拥有的文件，不能无边界扫描整个下载根目录。
- 识别 `movie.nfo`、`tvshow.nfo`、同名 NFO、`poster`、`fanart`、`folder`、季图、字幕和常见视频格式。
- 安全解析 XML/NFO，处理常见编码；解析失败时保留原文件，不写入乱码。
- 排除 sample、预告片、校验文件、说明文件和非正片附件。
- 识别电影、单季剧集、多季合集、特别篇、剧场版和混合发布包。

### FR-06 元数据匹配与合并

- 先尝试 MoviePilot 原生识别和现有公共来源精确匹配。
- 匹配至少考虑规范化标题、别名、年份、类型、季号、集数、单集编号和文件结构。
- 公共来源精确命中时沿用其 `media_source + media_id`，本地资料只补充缺失字段和图片。
- 无精确命中时生成 `piggokids` 本地媒体条目。
- 每个合并字段都记录来源和置信度；NFO 与文件名、年份或季集冲突时不得静默覆盖。
- 插件不得把全网搜索摘要或 AI 推断的简介直接当成已验证事实。

### FR-07 插件媒体来源

- 规范来源标识为 `piggokids`。
- `media_id` 必须稳定、可重复生成且不暴露 passkey。优先使用站点条目 ID；缺失时使用规范化字段和内容指纹生成本地 ID。
- 电影、剧集、季、特别篇和合集不能共用一个模糊身份。
- 插件要能按来源 ID 返回 MoviePilot 所需的媒体详情、图片和辅助信息。
- 原生识别失败时，插件向 MoviePilot 返回有效的 `media_source + media_id` 组合，使整理链可以继续。

### FR-08 整理、NFO 与图片

- 整理前生成目标路径预览并检查覆盖、同名、跨文件系统硬链接和权限风险。
- 高置信度且无冲突的任务自动调用 MoviePilot 整理。
- TMDb 不存在时，生成 Kodi/Emby/Jellyfin 可读取的本地 NFO、海报和背景图。
- 优先保留随包高质量图片；站点图片或公共来源图片必须记录来源。
- 默认保留做种文件，优先使用 MoviePilot 配置的硬链接或复制策略，不能移动或破坏原始下载。
- 整理完成后触发 MoviePilot 已配置媒体服务器的媒体库刷新。

### FR-09 自动化规则和冲突队列

- 用户可以启用或停用自动下载、自动识别、自动整理和自动刷新。
- 支持最低自动化置信度配置，但内置硬性冲突不能通过简单降低阈值绕过。
- 以下情况必须进入冲突队列：同名多候选且无年份、电影/剧集类型冲突、季号不明、多季混包无法拆分、NFO 与文件结构冲突、目标覆盖已有媒体。
- 冲突队列显示证据、候选、建议动作和重试入口。
- 用户确认后的规则可以保存为可复用解析规则，减少同类资源再次人工处理。

### FR-10 TMDb 辅助与贡献草稿

- TMDb API 只用于搜索、读取详情、图片和已存在条目的变化监控。
- 已有条目精确命中时可清理 MoviePilot 本地识别缓存并触发重新识别或刮削。
- 缺失或不完整时生成贡献草稿，包含建议字段、图片清单、来源 URL、冲突提示和 TMDb 搜索结果。
- 插件不通过 API 或浏览器自动提交公共数据库修改。
- 豆瓣和 Bangumi 同样只作为读取候选来源，不承诺通过公开 API 创建或编辑公共条目。

### FR-11 任务记录、通知与恢复

- 每个任务保留状态迁移、最近错误、重试次数、识别决策、整理结果和媒体库刷新结果。
- 支持从“抓取、下载、扫描、识别、整理、刷新”任一失败阶段重试，已成功阶段不得重复产生副作用。
- 通知中只显示资源标题、阶段和可操作的错误摘要，不显示密钥、完整私密 URL、Cookie 或绝对敏感路径。
- 插件禁用、升级或 MoviePilot 重启后，未完成任务可以恢复。

## 7. 自动化状态

标准任务状态如下：

```text
DISCOVERED
-> SELECTED
-> DOWNLOAD_SUBMITTED
-> DOWNLOADING
-> DOWNLOADED
-> SCANNING
-> MATCHING
-> READY_TO_TRANSFER
-> TRANSFERRING
-> LIBRARY_REFRESHING
-> COMPLETED
```

任一阶段可进入 `RETRYABLE_FAILED`；证据冲突进入 `NEEDS_REVIEW`；用户忽略后进入 `IGNORED`。所有状态迁移必须幂等并记录时间和原因。

## 8. V2 / V3 兼容要求

### MoviePilot V3

- 主实现位于 `plugins.v3/piggokidsmetadata/`，索引登记到 `package.v3.json`。
- 优先使用 `app.sdk` 和 V3 稳定扩展合同。
- 注册 `piggokids` 插件媒体来源，并实现识别、搜索、媒体详情、图片和辅助信息所需模块合同。
- 使用下载加入、下载完成、整理完成/失败等宿主扩展点建立任务闭环。
- 通用媒体身份始终使用 `media_source + media_id`。

### MoviePilot V2

- 兼容实现位于 `plugins.v2/piggokidsmetadata/`，索引登记到 `package.v2.json`。
- 使用 V2 可用的插件事件、页面、API 和识别增强能力实现相同用户流程。
- V2 若没有 V3 等价媒体来源合同，应通过识别增强、本地元数据登记和手动整理调用实现兼容，不伪造远端 ID。
- V2/V3 可以有内部适配差异，但配置字段、任务状态、用户页面术语和最终整理结果应保持一致。

## 9. 页面需求

插件至少提供以下页面或标签：

- `候选资源`：RSS 候选、筛选、选择下载、粘贴链接。
- `下载任务`：下载状态、hash 脱敏标识、关联目录、重试。
- `识别结果`：采用身份、字段来源、置信度和目标路径预览。
- `待处理`：冲突原因、候选选择、规则保存。
- `已完成`：整理位置、媒体服务器刷新结果、TMDb 状态。
- `设置`：RSS、定时周期、下载分类/目录、自动化开关、置信度、NFO 与图片策略。

页面不显示完整 RSS 私密参数、下载令牌、Cookie、MoviePilot API Key 或下载器凭据。

## 10. 安全与数据要求

- Cookie、passkey、下载 token、GitHub Token、MoviePilot API Key 和媒体服务器 Token 不得写入源码、文档、普通日志或通知。
- URL 脱敏要覆盖 query 参数、路径型 token 和日志异常对象。
- 插件运行数据写入 MoviePilot 插件数据目录，不写入插件源码目录。
- 文件扫描必须限制在任务拥有的下载路径内，并防止路径穿越和符号链接逃逸。
- 所有写文件、整理和覆盖动作使用 MoviePilot 宿主能力并进行目标冲突检查。
- 插件与 MoviePilot 共用 Python 环境，依赖声明必须保守，不要求宿主降级核心库。

## 11. 验收标准

第一版完成需同时满足：

1. V2 和 V3 插件市场都能发现、安装、启用、禁用和重载插件。
2. 可以拉取一个脱敏配置的 PigGo RSS，并对重复条目稳定去重。
3. 可以从 RSS 候选或粘贴链接调用 MoviePilot 下载器，并在重启后继续关联下载任务。
4. 下载完成后可以按 hash 和文件列表定位内容包，解析至少一种电影 NFO 和一种剧集 NFO，并识别常见海报/背景图。
5. TMDb 精确命中时沿用 TMDb 身份；TMDb 无条目时可以生成稳定 `piggokids` 身份。
6. 一个高置信度电影样例和一个高置信度剧集样例可以自动整理并被 Emby/Jellyfin 读取本地 NFO 与图片。
7. 一个多季混包或同名冲突样例必须进入待处理队列，不能错误自动入库。
8. 重复下载完成事件和重复整理重试不会产生重复文件或重复媒体条目。
9. 日志、页面、通知和导出中不出现 passkey、Cookie、token 或完整私密下载 URL。
10. 修改先在本地通过 JSON、Python 编译、单元测试和真实 V2/V3 宿主验证；向用户展示变更后，获得明确同意才能提交或推送。

## 12. 实施阶段

### 阶段一：识别闭环最小版本

实现任务数据模型、链接脱敏、下载映射、内容包扫描、NFO/图片解析、`piggokids` 身份和整理预览。先用手工指定本地下载任务验证闭环。

### 阶段二：RSS 与 MoviePilot 下载集成

实现 RSS 拉取、候选页面、粘贴链接、下载提交、hash 跟踪、状态恢复和高置信度自动整理。

### 阶段三：公共来源匹配与冲突规则

接入 TMDb 等读取来源，完善标题别名、年份、季集、合集拆分、置信度和待处理队列。

当前进度：`0.3.0` 已完成 MoviePilot TMDb 读取链的保守精确匹配、标题别名/类型/年份/季冲突拦截，以及不含私密链接和绝对路径的只读贡献草稿；合集拆分、可编辑待处理队列和公共来源搜索结果展示仍待后续实现。

### 阶段四：双版本和真实环境验收

完成 V2/V3 适配，在用户本地 MoviePilot、下载器和 Emby/Jellyfin 环境中验证安装、下载、整理、刷新和重启恢复。

## 13. 实施前仍需从本地实例确认的信息

以下信息不是需求缺口，但会影响联调方式。只记录类型，不在文档中记录敏感值：

- MoviePilot 当前具体版本，以及 V2、V3 是否各有测试实例。
- MoviePilot 本地访问地址和认证方式。
- 部署方式与下载目录、媒体目录的宿主机/容器映射。
- 下载器类型、下载分类/tag 使用方式和完成后保留目录结构的情况。
- 媒体服务器类型，以及希望刷新的儿童动画媒体库名称。
- 一个电影样例、一个单季剧集样例和一个合集/冲突样例。
- PigGo RSS 的实际字段格式；私密 URL 只在本地配置中录入，不写入仓库。

## 14. 仓库与协作约束

- 目标仓库为用户自己的 `xianglongwei/MoviePilot-Plugins` 本地克隆。
- 当前仓库已有自维护的 `MediaCoverGenerator`；新增 `PigGoKidsMetadata` 后，只保留这两个自维护插件及其必要资源，不恢复上游其它插件。
- 所有修改先在当前工作分支完成并验证。
- 未经用户明确确认，不创建远程 PR、不合并到 `main`、不推送 GitHub。
- 每次准备发布时，先向用户展示修改摘要、文件列表、验证结果和风险，再等待批准。
